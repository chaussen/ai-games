## The defect (from Design's M0.2 report, R4-D022)

R4-D020/D021's overshoot-forgiveness for 上+木(top)→末 is approach-direction-dependent:

| Approach | Result |
|---|---|
| North / South | locks 末 correctly |
| East / West | silent snap-back — host stays bare 木, 上 returns to inventory |

Confirmed with real dispatched drags at both 8-step and 60-step interpolation (not a sampling artifact). Control test at ~200px overshoot correctly snaps back — the forgiveness radius (1.25 cell-widths) is NOT the bug.

**Root cause (Design instrumented `updateZoneOverlay` directly):** the fallback resolves to `lastValidTarget` — the last zone the pointer *hovered* before exiting the cell. A lateral approach crosses the left/right band on its way toward the top band; if the pointer exits the cell before a sample lands purely inside the top band, the fallback freezes on `left`/`right`, resolution fails validity, silent snap-back.

## The ruling — what to build

**Zone resolution is stateless: the resolved zone is a pure function of the release position. Hover history is never a resolution input.**

1. **In-cell release:** resolve the zone from the release point via the existing `cellLocalZone()` geometry (unchanged since R4-D011 — do not touch the geometry).
2. **Overshoot release** (outside the host cell but within the existing 1.25 cell-width forgiveness radius): **clamp/project the release point onto the host cell's rect**, then run the same `cellLocalZone()` on the projected point. A release 6px above the cell projects into the top band regardless of how the pointer got there.
3. **Delete `lastValidTarget` as a resolution input.** It may survive only as an internal detail of overlay painting if needed — but see invariant below, which should make it unnecessary entirely.
4. **Host-cell selection is unchanged** (nearest valid adjacent host within radius, per D016/D021). Only zone-within-cell resolution changes.

**Overlay/resolver parity invariant (new, binding):** the drag-time zone overlay and the release resolver must call the **same single function** `resolveZone(pointerPos, hostCell)`. At every pointer position during a drag, the zone painted must equal the zone a release at that exact position would produce. No second code path, no cached state. This is what makes silent snap-backs honest: if no zone is painted, release does nothing; if a zone is painted, release resolves there.

## What NOT to do

- Do not special-case east/west, the top band, or 末. The fix must be direction- and zone-agnostic or it is the wrong fix.
- Do not widen the forgiveness radius (A7 proved it's correct).
- Do not touch `cellLocalZone()` geometry (R4-D011 verified it clean).
- Do not verify anything via direct handler calls.

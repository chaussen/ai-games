## Change 1 — Zone picker rebalance + drag overlay  *(fixes R4-D008)*

### 1a. New zone geometry (replaces current cellLocalZone)
Express in cell-relative fractions, not px, so it survives any cell size:

| Zone | Region (x, y as fraction of cell) |
|---|---|
| `top` | y < 0.33 — **full width** |
| `bottom` | y > 0.67 — **full width** |
| `left` | 0.33 ≤ y ≤ 0.67 AND x < 0.50 |
| `right` | 0.33 ≤ y ≤ 0.67 AND x ≥ 0.50 |
| `enclose` | **REMOVED from M0 gesture entirely** (deferred to M1 with 囗 — R4-D011) |
| `under` | not in M0 (no 灬 recipe live) — unchanged |

Rules:
- Every pixel of the cell resolves to exactly one of the four directional zones. **No dead zone, no center-special-case.** A release at the visual center resolves to `left` or `right` by the x-midline.
- y-check runs BEFORE x-check (inverts the current bug).
- Remove all `enclose` resolution paths from the drop handler. If any recipe table entry references enclose, comment it out with `// M1: enclose` — do not delete.

### 1b. Drag-time zone overlay (mandatory, not optional)
- While carrying a component AND the pointer is over a valid host cell: draw the 4-zone subdivision on that cell (thin lines, ~15% alpha) and highlight the currently-resolved zone (fill ~25% alpha, host-color tint).
- Overlay is drawn **on the world cell itself** — it is world-anchored feedback, not a panel. (This is what keeps §9.1 Q2 a PASS: no detached UI.)
- Touch: the highlight must be readable with a fingertip occluding the cell center — ensure the active-zone fill extends to the cell edge so it's visible around the finger.
- Overlay appears/disappears with hover; zero persistence after release.

## Change 2 — Wire 末 (fixes R4-D009)

- New stability-registry entry live in build: **上 attached at `top` slot of a standalone 木 → 末** (mò, "treetop/tip").
- Lock treatment identical to 林/炎/沐: snap, glow, persist, ambient pronunciation "mò".
- Effect: **the tree grows one cell taller** — glyph visually extends into the cell above (if that cell is empty; if occupied, the composition still locks but growth is suppressed). Player can harvest from / see over the grown tree if the build has any elevation/vision logic; if not, the visual growth alone is the M0 effect.
- 上 onto 林, 森, 水, 火, 石, or a 末 → normal fizzle (this is now healthy variance, not a defect: 上 has one success path and several interesting failures).
- 上 remains a "mark" — it is consumed into the compound like any component. No separate mark-verb for M0 (OPEN-5 data will come from how 末 feels).
